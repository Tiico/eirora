# Eirora

## Development standards

These rules apply to every agent working in this repo.
They override an agent's default behavior.

### Decisions

- Weigh technical decisions by quality, simplicity, robustness, scalability and long-term maintainability.
  Give development cost little weight: the more expensive but cleaner solution is usually the right one.
- When offering the user a choice (which task, which approach, which option), present 2–4 real alternatives with their trade-offs as clickable options (e.g. Claude Code's `AskUserQuestion`), never as a prose list the user has to answer by typing.
  Put the recommended option first.

### Bugs and testing

- Start every bug fix by reproducing the bug end-to-end, as close as possible to how a player would encounter it (running client, headless simulation, real device), before touching the code.
  Then fix it and keep the reproduction as a regression test.
- When testing the product end-to-end, be picky about the UI and obsess over pixel perfection.
  If something clearly looks off, fix it even if it is unrelated to the current task.
- Hold the same bar for engineering hygiene: lint errors, failing tests and flaky tests get fixed when you see them, even if you did not cause them.

### Plans

- Keep plans extremely concise; sacrifice grammar for brevity.
- End every plan with a list of unresolved questions for the user, if any.

### Files and commits

- Never add an agent (Claude or otherwise) as co-author or attribution in commit messages.
- Never edit `CHANGELOG.md` or any file marked as auto-generated by hand.
- When writing or substantially editing long Markdown files, put each full sentence on its own line.
